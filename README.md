# GachaSLop

Локальное приложение: React + TypeScript, Go API и SQLite для импорта и анализа
истории круток из Genshin Impact, Honkai: Star Rail, Zenless Zone Zero и Wuthering Waves.

Это один адаптивный сайт для десктопного и телефонного браузера, не отдельное
мобильное приложение.

Сейчас реализованы:

- адаптивный интерфейс: обзор, история, аккаунты и окно импорта;
- реальные счётчики с пометкой неполной истории и серверные фильтры;
- баннеры и календарь всех четырёх игр с данными через Go API;
- асинхронный импорт по временной ссылке истории;
- официальные игровые history API HoYoverse и Kuro;
- инкрементальная загрузка HoYo по `end_id`;
- идемпотентное сохранение и keyset-пагинация;
- отдельные pity-группы, включая дополнительные пулы HSR 3.4+;
- SQLite с WAL и версионируемыми миграциями;
- readiness/liveness, graceful shutdown и структурированные логи;
- защита от SSRF и исключение `authkey`/`record_id` из БД и логов.

HoYo-адаптер в текущей версии рассчитан на global-серверы. WuWa поддерживает
global и CN, выбирая API по домену исходной ссылки.

## Запуск

Требуются Go 1.25+ и Node.js 22.12+ (рекомендуется Node 24).

```bash
npm --prefix web ci
npm --prefix web run build
go build -trimpath -o bin/gachaslop-api ./cmd/api
./bin/gachaslop-api
```

Откройте **http://127.0.0.1:8080**. Go раздаёт `web/dist` и `/api/v1` с одного
адреса. При пустой базе приложение предложит импорт; демо-крутки в SQLite не
добавляются. Для первого импорта нужна персональная временная ссылка из игры.

Настройки перечислены в `.env.example`. `.env` автоматически не читается:
экспортируйте переменные в shell либо используйте загрузчик IDE/контейнера.
По умолчанию сервер слушает только `127.0.0.1:8080`, база — `data/gachaslop.db`,
фронтенд — `WEB_DIR=web/dist`. Запускайте бинарник из корня проекта либо задавайте
абсолютные `DATABASE_DSN` и `WEB_DIR`. Без сборки фронтенда сервер работает в API-only режиме.

Проверка:

```bash
curl http://localhost:8080/readyz
```

## Основной сценарий API

Пользователь сначала открывает страницу истории в игре, а локальный помощник
или пользователь копирует полный URL. URL является секретом и отправляется
только в теле запроса:

```bash
curl -X POST http://localhost:8080/api/v1/sync-jobs \
  -H 'Content-Type: application/json' \
  -d '{
    "game": "genshin",
    "source_url": "https://webstatic-sea.hoyoverse.com/...?..."
  }'
```

API вернёт `202 Accepted` и ID задания. Статус опрашивается отдельно:

```bash
curl http://localhost:8080/api/v1/sync-jobs/JOB_ID
```

После первой загрузки передавайте `account_id`. Тогда HoYo-адаптер остановит
пагинацию на последней известной записи:

```json
{
  "game": "hsr",
  "account_id": "ACCOUNT_ID",
  "source_url": "FULL_PRIVATE_HISTORY_URL"
}
```

Чтение данных:

```text
GET /api/v1/accounts
GET /api/v1/accounts/{id}
GET /api/v1/accounts/{id}/pulls?limit=50&pool_family=limited_character
GET /api/v1/accounts/{id}/pity
GET /api/v1/banners?game=genshin
```

Баннеры доступны без импорта истории. Значения `game`: `genshin`, `hsr`, `zzz`,
`wuwa`. Для HoYo используется публичный [Ennead API](https://github.com/torikushiii/hoyoverse-api),
для WuWa — официальные объявления Kuro. Последний успешный ответ сохраняется
в SQLite, срок свежести — 15 минут; при сбое источника возвращается кеш с
`stale: true`. Без сохранённых данных API отвечает `503` с `Retry-After: 60`.
Фронтенд проверяет расписание раз в минуту и пересчитывает таймер каждую секунду.
Дата обновления и источник видны в интерфейсе.

Контракт API описан в [api/openapi.yaml](api/openapi.yaml), устройство слоёв и
план перехода на PostgreSQL — в [docs/architecture.md](docs/architecture.md).

## Разработка

Два терминала, hot reload фронтенда:

```bash
make run
```

```bash
make frontend-dev
```

Vite покажет адрес (обычно http://127.0.0.1:5173). Запросы `/api`, `/healthz`,
`/readyz` проксируются на Go `127.0.0.1:8080`; CORS не нужен. При изменении
порта API обновите proxy в `web/vite.config.ts`.

```bash
make test
make vet
make frontend-test
make build
cd web && npm run test:e2e
```

E2E запускает отдельный Go-сервер на `127.0.0.1:18080` с временной in-memory
SQLite, использует установленный Google Chrome. Перед тестами соберите фронтенд.
Покрываются реальный API/пустая база/ошибка импорта и UI-сценарии с фикстурами
(успех импорта, статистика, фильтры, пагинация, мобильная верстка, баннеры).
Реальные персональные credentials в тестах не используются.

Дополнительно, при запущенном основном сервере: `cd web && node scripts/smoke-banners.mjs`.
Это необязательная сетевая проверка живых данных и изображений всех четырёх игр
на desktop и телефонной ширине; снимки сохраняются в `web/test-results/`.

## Контейнер

```bash
docker build -t gachaslop .
docker run --rm -p 127.0.0.1:8080:8080 -v gachaslop-data:/app/data gachaslop
```

Образ собирает фронтенд и Go. SQLite сохраняется в named volume. Контейнер
слушает `0.0.0.0:8080` внутри, но пример публикует порт только на localhost.

## Ограничения текущей версии

- Будущие баннеры показываются только после публикации источником; отсутствие
  анонса не заменяется демо-данными. Ennead — сторонний сервис без нашего SLA.
- Ennead не предоставляет выбор игрового региона. Для WuWa используется
  английское объявление и азиатское server time (UTC+8); старт «после обновления»
  берётся из планового окончания техработ. Сроки других серверов могут отличаться.
  Интерфейс предупреждает об этом и переводит даты в часовой пояс браузера.
- WuWa парсится из HTML объявлений: изменение формата может потребовать обновления
  адаптера. Неизвестные даты остаются пустыми, а не берутся из срока видимости новости.
- Для персонажей HoYo большие арты подбираются по ID из каталога Enka и
  загружаются с enka.network; маленькие иконки остаются в списках. Каталог кешируется
  в памяти на 6 часов; его сбой не блокирует расписание. У WuWa пока используются
  официальные обложки объявлений. Шрифты упакованы локально в сборку.
- Автоматического извлечения URL из клиента игры нет. Вставляйте полную
  персональную ссылку, полученную самостоятельно; не публикуйте её.
- Браузер хранит в sessionStorage только ID текущего задания. URL очищается
  после отправки/закрытия окна и не сохраняется в localStorage, query cache или БД.
- Неполная история отображается как `≥ N`. Гарант неизвестен; интерфейс не
  обещает количество круток до гарантированного выпадения.
- Pity пока рассчитывается из истории на сервере; при росте объёмов нужен
  отдельный агрегированный read model. Summary уже вычисляется SQL-агрегацией.

API пока не содержит авторизации и предназначен для локального использования.
Не публикуйте его в интернет до добавления identity/tenant middleware и rate
limiting.
